# CopyCodeReference 개발지시서

## 1. 프로젝트 개요

Visual Studio 2022의 코드 편집기에서 사용자가 선택한 코드 블록을 다음 정보와 함께 클립보드에 복사하는 VSIX 확장 프로그램을 개발한다.

복사 대상은 다음 세 가지다.

1. 현재 문서의 전체 파일 경로
2. 선택한 영역의 시작/종료 줄 번호
3. 사용자가 실제 선택한 코드 문자열

확장 프로그램은 **Visual Studio Code용 확장 프로그램이 아니라 Visual Studio 2022용 VSIX Extension**이다.

# 3. 핵심 기능

예를 들어 다음 코드가:

```csharp
private async Task LoadAsync()
{
    var data = await repository.LoadAsync();
    Items.AddRange(data);
}
```

다음 파일의 42~46줄에 있다고 가정한다.

```text
D:\Project\SampleApp\ViewModels\MainViewModel.cs
```

사용자가 해당 코드를 선택하고 `Copy Code Reference` 명령을 실행하면 Clipboard에 다음 문자열이 저장되어야 한다.

```text
D:\Project\SampleApp\ViewModels\MainViewModel.cs:42-46

private async Task LoadAsync()
{
    var data = await repository.LoadAsync();
    Items.AddRange(data);
}
```

한 줄만 선택한 경우:

```text
D:\Project\SampleApp\ViewModels\MainViewModel.cs:42

var data = await repository.LoadAsync();
```

형식을 사용한다.

# 4. 핵심 설계 원칙

이 확장은 코드의 의미를 분석하는 도구가 아니다.

필요한 정보는 Visual Studio Editor가 이미 제공하는 다음 정보만 사용한다.

```text
Active Document
        ↓
IWpfTextView
        ↓
ITextSelection
        ↓
SnapshotSpan
        ↓
FilePath + Line Range + Selected Text
        ↓
Clipboard
```

따라서 v0.1에서는 Roslyn `Workspace`, `Compilation`, `SemanticModel` 등을 사용하지 않는다.

의존성과 구현 복잡도를 최소화하고 다음 흐름만 정확하게 구현한다.

```text
선택 영역
→ 파일 위치 확인
→ 줄번호 계산
→ 출력 문자열 생성
→ Clipboard 저장
```

# 5. 기술 스택

Visual Studio 2022의 기존 in-process 확장 모델을 사용한다.

**채택 기술**

```text
Visual Studio 2022
C#
VSIX
Visual Studio SDK 17.x
Community.VisualStudio.Toolkit.17
Visual Studio Editor API
```

Microsoft의 현재 VSIX 입문 문서에서는 명령 기반 확장의 시작점으로 `VSIX Project w/Command (Community)` 템플릿을 사용하고 있다. 이 템플릿에는 Command 등록 구조가 기본으로 포함되어 있다.

Community Toolkit은 VSSDK 위에 구축된 wrapper로, 기존 VSSDK의 기능을 유지하면서 Command 및 Visual Studio 서비스 접근 코드를 단순화한다.

## 기술 대안

| 방식                            | 장점                             | 단점                      | 결정               |
| ----------------------------- | ------------------------------ | ----------------------- | ---------------- |
| Raw VSSDK                     | 모든 API 직접 제어                   | boilerplate와 COM 코드가 많음 | 보류               |
| **VSSDK + Community Toolkit** | 구현 단순, VS2022 지원, Editor 접근 용이 | Toolkit 의존성             | **채택**           |
| VisualStudio.Extensibility    | 새로운 확장 모델                      | 본 프로젝트 기능 대비 구조가 복잡     | 보류               |
| EnvDTE 중심                     | 간단한 자동화에 편리                    | Legacy COM API 의존도가 높음  | 핵심 구현에서는 사용하지 않음 |

# 6. 지원 범위

v0.1의 공식 지원 범위는 다음이다.

```text
Visual Studio 2022
Windows x64
일반 Text Editor
```

VSIX Manifest의 Visual Studio 대상 범위는 다음으로 한다.

```xml
Version="[17.0,18.0)"
```

Microsoft 문서에서도 Visual Studio 2022 전용 InstallationTarget에 `[17.0,18.0)` 범위를 사용한다.

v0.1에서는 ARM64를 필수 지원하지 않는다.

향후 필요할 경우 Managed VSIX는 ARM64 InstallationTarget을 추가할 수 있다.

# 7. 개발 시작 순서

GitHub Repository를 먼저 생성하지 않는다.

다음 순서로 진행한다.

```text
1. Visual Studio 확장 개발 환경 확인
2. D:\Project\CopyCodeReference 로컬 프로젝트 생성
3. VSIX 기본 프로젝트 빌드
4. Experimental Instance 실행 확인
5. Copy Code Reference 기능 구현
6. 기본 기능 검증
7. Git 저장소 초기화
8. 첫 commit
9. GitHub에 빈 CopyCodeReference Repository 생성
10. origin 연결
11. main branch push
```

이 순서를 사용하면 GitHub Repository 생성 전에 VSIX 프로젝트 구조와 빌드 환경이 정상인지 먼저 검증할 수 있다.

Community Toolkit API를 우선 사용한다.

개념적인 접근:

```csharp
DocumentView documentView =
    await VS.Documents.GetActiveDocumentViewAsync();

if (documentView?.TextView == null)
{
    return;
}
```

Microsoft의 현재 VSIX 예제에서도:

```csharp
VS.Documents.GetActiveDocumentViewAsync()
```

를 사용하여 현재 활성 Editor의 `TextView`와 `TextBuffer`에 접근한다.

# 17. Selection 획득

활성 Editor에서:

```text
IWpfTextView
    ↓
ITextSelection
    ↓
SnapshotSpan
```

순서로 선택 영역을 획득한다.

기본 로직:

```csharp
var selection = documentView.TextView.Selection;

if (selection.IsEmpty)
{
    return;
}

var span =
    selection.StreamSelectionSpan.SnapshotSpan;
```

`ITextSelection`은 `IsEmpty`, `Start`, `End`, `SelectedSpans`, `StreamSelectionSpan` 등의 selection 정보를 제공한다.

`StreamSelectionSpan`은 현재 selection을 stream selection 형태로 제공한다.

---

# 18. 파일 경로 획득

현재 TextBuffer에 연결된 `ITextDocument`에서 실제 파일 경로를 얻는다.

개념적인 형태:

```csharp
ITextDocument textDocument;
```

파일 경로:

```csharp
string filePath = textDocument.FilePath;
```

Microsoft Visual Studio SDK에서 `ITextDocument`는 파일 시스템에 존재하는 `ITextBuffer` 문서를 나타내며, `FilePath`는 문서의 파일명과 경로를 제공한다.

v0.1 출력에는 반드시 **absolute path**를 사용한다.

예:

```text
D:\Project\SampleApp\ViewModels\MainViewModel.cs
```

Solution 상대경로 변환은 하지 않는다.

---

# 19. 선택 문자열 획득

선택 문자열:

```csharp
string selectedText = span.GetText();
```

선택 텍스트에는 어떠한 formatting도 적용하지 않는다.

다음 처리를 금지한다.

```text
Trim()
TrimStart()
TrimEnd()

들여쓰기 보정
Tab → Space 변환
CRLF → LF 변환
Trailing whitespace 제거
```

사용자가 실제 선택한 텍스트를 그대로 복사해야 한다.

---

# 20. 시작 줄 계산

Visual Studio Editor 내부 line number를 사용자 표시용으로 변환한다.

출력 줄 번호는 반드시 **1-based**여야 한다.

개념적인 구현:

```csharp
var snapshot = span.Snapshot;

int startLine =
    snapshot.GetLineNumberFromPosition(
        span.Start.Position) + 1;
```

---

# 21. 종료 줄 계산

`SnapshotSpan.End`는 selection의 exclusive end라는 점을 고려한다.

따라서 단순히:

```csharp
snapshot.GetLineNumberFromPosition(span.End.Position)
```

으로 처리하면 안 된다.

예를 들어 10~12번째 줄 전체를 선택했는데 selection end가 13번째 줄 첫 위치에 존재하면:

```text
잘못된 결과:
10-13
```

이 나올 수 있다.

실제 마지막 선택 위치를 기준으로 계산한다.

```csharp
int endPosition =
    span.Length > 0
        ? span.End.Position - 1
        : span.End.Position;

int endLine =
    snapshot.GetLineNumberFromPosition(endPosition) + 1;
```

단, snapshot boundary를 검사하여 범위 오류가 발생하지 않도록 한다.

---

# 22. 문자열 생성

문자열 생성 코드는 Visual Studio API 의존 코드와 분리한다.

파일:

```text
Services\CodeReferenceBuilder.cs
```

예상 구조:

```csharp
internal static class CodeReferenceBuilder
{
    public static string Build(
        string filePath,
        int startLine,
        int endLine,
        string selectedText)
    {
        string location =
            startLine == endLine
                ? $"{filePath}:{startLine}"
                : $"{filePath}:{startLine}-{endLine}";

        return
            location +
            Environment.NewLine +
            Environment.NewLine +
            selectedText;
    }
}
```

이 클래스는 Visual Studio SDK에 의존하지 않아야 한다.

---

# 23. Clipboard

생성된 문자열 전체를 Clipboard에 저장한다.

개념:

```csharp
Clipboard.SetText(text);
```

성공 시:

```text
MessageBox 표시 금지
팝업 표시 금지
```

사용자가 자주 실행하는 명령이므로 성공할 때마다 알림 창을 띄워서는 안 된다.

필요하다면 Visual Studio Status Bar에 짧은 성공 메시지를 출력할 수 있으나 v0.1 필수 기능은 아니다.

---

# 24. 선택 영역이 없는 경우

다음 조건:

```csharp
selection.IsEmpty == true
```

일 때는 즉시 종료한다.

반드시 다음 조건을 만족해야 한다.

```text
Clipboard 변경 없음
현재 줄 자동 복사 없음
MessageBox 없음
Exception 없음
```

현재 caret 줄을 자동으로 복사하는 기능은 별도 기능으로 취급한다.

---

# 25. 저장되지 않은 문서

```text

실제 FilePath가 없는 Editor
```

absolute path를 얻을 수 없으면 명령을 수행하지 않는다.

기존 Clipboard는 유지한다.

# 26. 비텍스트 Editor

다음 상황에서 Command가 실행되어도 Visual Studio가 crash해서는 안 된다.

```text
Designer
XAML Designer
Resource Editor
Image Editor
Solution Explorer
Tool Window
```

Active `TextView`를 얻을 수 없다면 즉시 종료한다.

---

# 27. Box Selection

Visual Studio의 `Alt` 기반 Box/Column Selection은 일반 selection과 다른 형태가 될 수 있다.

v0.1 공식 지원 범위:

```text
일반 Stream Selection
```

Box Selection에서도 crash하지 않아야 하지만 별도 formatting을 구현하지 않는다.

향후 `SelectedSpans` 기반 처리를 검토한다.

---

# 28. Threading

Command는 async 방식으로 구현한다.

필요한 UI 접근에서는:

```csharp
await Package.JoinableTaskFactory
    .SwitchToMainThreadAsync();
```

패턴을 사용한다.

Community Toolkit 공식 예제 역시 active editor를 처리하기 전에 UI thread 전환 패턴을 사용한다.

동기 `GetService()`보다 async API를 우선한다.

---

# 29. Command 실행 흐름

최종 Command는 다음 순서로 동작한다.

```text
Copy Code Reference 실행
          ↓
Active Document 확인
          ↓
TextView 확인
          ↓
Selection 확인
          ↓
ITextDocument 확인
          ↓
FilePath 획득
          ↓
SnapshotSpan 획득
          ↓
StartLine 계산
          ↓
EndLine 계산
          ↓
선택 Text 획득
          ↓
CodeReferenceBuilder.Build()
          ↓
Clipboard.SetText()
```

중간 조건을 만족하지 못하면 exception 대신 가능한 한 early return을 사용한다.

# 30. 예외 처리

Extension 내부 exception이 Visual Studio process까지 전달되어서는 안 된다.

특히 다음 경우를 처리한다.

| 상황                 | 처리         |
| ------------------ | ---------- |
| Active document 없음 | return     |
| TextView 없음        | return     |
| Selection 없음       | return     |
| FilePath 없음        | return     |
| Selection span 오류  | 안전하게 종료    |
| Clipboard 오류       | catch 후 종료 |
| Editor disposed    | 안전하게 종료    |
| VS 종료 중            | 안전하게 종료    |

정상적인 비실행 조건은 exception으로 취급하지 않는다.

# 33. End Line 필수 테스트

다음 파일이 있다고 가정한다.

```text
1 AAA
2 BBB
3 CCC
4 DDD
```

1~3줄을 선택하고 selection end가 4번째 줄 시작 위치에 있는 경우:

```text
올바른 결과:
:1-3
```

이어야 한다.

다음 결과가 나오면 실패다.

```text
잘못된 결과:
:1-4
```

이 테스트는 반드시 수행한다.

# 36. 첫 Commit

프로젝트가 정상적으로 빌드되는 상태에서 첫 commit을 생성한다.

```powershell
git add .
git commit -m "chore: initialize CopyCodeReference VSIX project"
```

첫 commit은 실행 가능한 기본 VSIX skeleton을 기준으로 한다.

기능 구현을 모두 끝낸 다음 한 번에 첫 commit을 만들지 않는다.

# 43. Definition of Done

v0.1은 다음 조건을 모두 만족해야 한다.

* Visual Studio 2022에서 프로젝트가 빌드된다.
* VSIX가 정상 생성된다.
* F5 실행 시 Experimental Instance가 열린다.
* Edit 메뉴에 `Copy Code Reference`가 표시된다.
* 일반 Text Editor에서 명령이 실행된다.
* 선택한 텍스트가 정확히 복사된다.
* 절대 파일 경로가 포함된다.
* 시작 줄번호가 정확하다.
* 종료 줄번호가 정확하다.
* 한 줄 선택은 `File.cs:10` 형식이다.
* 여러 줄 선택은 `File.cs:10-20` 형식이다.
* 코드의 whitespace가 유지된다.
* 선택이 없으면 Clipboard가 변경되지 않는다.
* FilePath가 없는 문서에서 crash하지 않는다.
* 비텍스트 Editor에서 crash하지 않는다.
* Clipboard 실패가 Visual Studio crash로 이어지지 않는다.
* Debug build가 성공한다.
* Release build가 성공한다.
* Git Repository의 기본 branch가 `main`이다.
* GitHub `CopyCodeReference` Repository에 push된다.
* README 내용이 실제 동작과 일치한다.

# 46. 최종 개발 기준

프로젝트 기준 디렉터리는 다음으로 고정한다.

```text
D:\Project\CopyCodeReference
```

프로젝트 관련 이름 역시 다음처럼 통일한다.

```text
Project     : CopyCodeReference
Solution    : CopyCodeReference
Namespace   : CopyCodeReference
Repository  : CopyCodeReference
Extension   : Copy Code Reference
Command     : Copy Code Reference
```

첫 번째 목표는 기능을 많이 넣는 것이 아니라 다음 한 가지 workflow를 정확하게 완성하는 것이다.

```text
Visual Studio 2022
        ↓
코드 선택
        ↓
Edit → Copy Code Reference
        ↓
파일 경로 + 줄번호 + 선택 코드 생성
        ↓
Clipboard 복사
```

이 workflow가 안정적으로 동작한 이후에만 추가 기능을 확장한다.
